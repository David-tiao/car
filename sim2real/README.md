# 实体小车模拟（Sim2Real）

> 工创智能搬运比赛 · ROS2 / Nav2 / 数字孪生可视化实验平台  
> 当前网页工程版本：**V12.0.0**  
> 本机项目目录：`/home/tao/Desktop/car/sim2real`  
> 网站启动命令：`car`  
> 本机访问地址：`http://127.0.0.1:8080/`

## 1. 项目介绍

本项目面向工创智能搬运小车比赛，使用浏览器构建比赛场地的二维数字孪生。平台既可以在**模拟运行**模式下验证栅格地图、障碍物布置、路径规划和物料搬运流程，也计划在**实车实时运行**模式下接收实体小车的底盘、视觉和雷达数据，将真实运动与导航状态可视化。

项目定位是**仿真、监控与联调工具**，而不是直接代替 STM32F4 的电机闭环控制器。网站当前不向实车发送运动指令。

## 2. 当前装置与理想装置

### 2.1 当前实际硬件

- **STM32F4**：底盘控制、执行机构以及与视觉模块的通信基础。
- **OpenMV H7 Plus**：二维码、颜色、物料及色环相关的视觉识别基础。
- **暂不接入雷达**：当前实车阶段不以激光雷达作为必需设备，后续再补充雷达和对应定位、导航流程。

> 当前硬件配置说明的是实体小车已有的组成，**不表示它已经向 ROS2 发布了 `/odom` 或能直接让网页同步运动**。

### 2.2 理想装置（本项目主要设计目标）

| 设备/软件 | 计划职责 |
| --- | --- |
| STM32F4 | 电机 PID、编码器采样、底盘控制、抓取机构执行与反馈 |
| OpenMV H7 Plus | 二维码、物料颜色、色环与目标位置识别；可选上传视觉画面和结果 |
| 树莓派 5（ROS2） | 车载计算机，串口接收 STM32F4 反馈，生成 `/odom` 和 TF，转发摄像头数据 |
| YDLIDAR 激光雷达（后续） | 发布 `/scan`，为定位、避障、SLAM / Nav2 提供扫描数据 |
| 树莓派 5 的 77° 摄像头 | 采集车载环境画面，通过网络传给网页服务器 |
| Ubuntu 电脑（ROS2 Humble） | 通过局域网订阅 ROS2 话题，运行 Nav2 相关工具、数据桥接和本网页服务器 |
| 浏览器 | 展示地图、规划路径、实际运动轨迹、激光扫描和双摄像头画面 |

**项目重点：以理想装置为系统架构设计基准；分阶段接入真实硬件。** 因此文档中的“计划接入”和“代码已支持”应与“实车联调成功”严格区分。

## 3. 系统整体数据流（理想架构）

```text
[实体小车]
  │
  ├─ STM32F4 ── 编码器/电机/机构反馈 ── USB/UART ───┐
  │                                                 │
  ├─ OpenMV H7 Plus ── 识别结果/USB图像 ────────────┤
  │                                                 ▼
  ├─ YDLIDAR（后续接入）── USB扫描数据 ──────── [树莓派 5 / ROS2]
  │                                                 │
  └─ 77° CSI摄像头 ── Picamera2 JPEG ───────────────┤
                                                    │
                              ┌─────────────────────┴──────────────────┐
                              │                                        │
                       ROS2 DDS（局域网）                        HTTP JPEG上传
                       /odom /scan /tf ...                           两路相机
                              │                                        │
                              ▼                                        ▼
                 [Ubuntu / ROS2 Humble / V12 网站服务器]
                              │
                 ROS2桥接 → HTTP数据接口 → 浏览器
                              │
                              ▼
                 [Sim2Real 网页：实时位置、速度、
                  雷达、Nav2、摄像头、实际轨迹]
```

### 3.1 底盘运动数据流（最优先打通）

1. **STM32F4**读取四轮编码器计数与电机状态；采样周期及实际串口协议以现有固件为准。
2. **STM32F4 → 树莓派 5**：通过 USB CDC 或 UART 传输带时间戳的编码器/轮速/机构反馈。
3. **树莓派底盘 ROS2 节点（待编写或对接）**：解析帧并计算麦克纳姆底盘的 `vx`、`vy`、`wz`，积分/融合得到 `x`、`y`、`yaw`，发布 `nav_msgs/msg/Odometry` 的 `/odom`，维护 `odom → base_link` TF。
4. **树莓派 → Ubuntu**：通过同一局域网的 ROS2 DDS 通信，Ubuntu 直接订阅 `/odom`，不需要 ROS Master。
5. **Ubuntu V12 桥接**：`ros2_visualization_bridge.py` 订阅 ROS2 数据，将 `/odom` 转为 JSON，POST 至本机网页服务器的 `/api/telemetry`；默认最高约 **15 Hz**。
6. **网页服务器**：缓存最新位置/速度，并通过 `GET /api/telemetry` 供浏览器获取。
7. **浏览器实车模式**：将位置配准到 2.4 m × 2.4 m 比赛地图，更新车体位置、航向、数值和实际轨迹；不能将 `/cmd_vel` 当成实测速度。

主要运动字段与单位：

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `x`, `y` | 底盘参考位置 | m |
| `yaw` | 底盘航向 | rad |
| `vx`, `vy` | 车体前后 / 横向速度 | m/s |
| `wz` | 车体角速度 | rad/s |
| `source`, `frame` | 数据来源、坐标系标识 | 字符串 |

**未完成的关键环节**：V12 网页包本身**没有 STM32F4 原始串口反馈解析与 `/odom` 发布节点**。需要结合实际 STM32 固件协议，在树莓派上实现或对接该节点，才能获得真正的实时运动。

### 3.2 雷达与导航数据流（后续接入）

1. YDLIDAR 通过 USB 接到树莓派 5，驱动发布 `/scan`（`sensor_msgs/msg/LaserScan`）。
2. 若需要定位和地图叠加，还应提供 `/map`、`/odom` 和完整 TF：`map → odom → base_link → laser_frame`。
3. 树莓派通过 DDS 将 `/scan` 等消息送到 Ubuntu；Nav2 或 SLAM 可在完成资源与网络方案后接入。
4. Ubuntu 的 `ros2_visualization_bridge.py` 将雷达、地图、Nav2 路径和代价地图转换为网页可绘制的数据。
5. 网页在「ROS2 导航与激光雷达」工作区显示激光扫描、地图、全局/局部路径、TF 状态和话题状态。

**当前实车不使用雷达**。雷达相关功能属于预留的理想装置架构；V12 不会在启动网站时自动启动 YDLIDAR 驱动、SLAM 或 Nav2。没有 TF 时，应使用激光局部视图，不能把扫描点强行叠加到全局地图。

### 3.3 双摄像头数据流

**OpenMV H7 Plus（规划中的车载 USB 接法）：**

```text
OpenMV 采集/识别 → USB虚拟串口 → 树莓派 openmv_usb_sender.py
→ HTTP POST /api/camera/openmv/frame → Ubuntu服务器
→ GET /api/camera/openmv/stream.mjpg → 浏览器
```

V12 附带的是 JPEG 取图和上传示例；与正在使用的 OpenMV 二维码/物料识别及 STM32 通信程序**仍需合并**，不能直接覆盖现有视觉主程序。识别结果的结构化上传也尚待实现。

**树莓派 5 的 77° 摄像头：**

```text
CSI摄像头 → Picamera2 → pi5_camera_sender.py
→ HTTP POST /api/camera/pi5/frame → Ubuntu服务器
→ GET /api/camera/pi5/stream.mjpg → 浏览器
```

摄像头画面走 HTTP 上传，不依赖雷达；摄像头的实时状态可从 `/api/cameras` 查询。真实帧率和延迟需要硬件与网络联调确定。

## 4. 网页的两种运行模式

### 4.1 模拟运行（Simulation）

**不需要实车在线。** 以静态比赛地图与设定参数为输入：

- 2400 × 2400 mm 场地，**5×5 / 25 格**，每格 480 × 480 mm；蛇形编号 `0–24`。
- 最多放置 **2 个障碍物**；点击格子封锁，再次点击同一格取消。
- 支持 **A*、Dijkstra、D* Lite** 路径实验和完整任务路线显示。
- 使用 260 × 290 mm 车体模型；地图显示的大格和底层碰撞计算相区分。
- 可配置二维码任务码、转盘位置与速度、物料抓取/放置、工位微调与伸缩夹爪。
- 按设定速度播放动画；**动画不等于真实实车反馈**。

> 现有网页默认“到另一个启停区”属于团队实验设置；上传的正式初赛规则要求任务完成后返回**抽签确定的启停区**。正式比赛验证时应切换为规则要求，不要混淆。

### 4.2 实车实时运行（Live）

**需要真实数据源在线。** 浏览器读取 Ubuntu 已经接收的 `/odom`、ROS2 可视化数据与摄像头图像：

- 实时显示速度、位置、航向、实际轨迹和规划轨迹对比。
- 显示 ROS2 `/scan`、`/map`、代价地图、Nav2 路径、TF 状态及诊断信息（各话题存在时）。
- 显示 OpenMV、树莓派 5 两路视频（各上传程序运行时）。
- 无数据时显示离线/等待状态；历史 CSV 回放不应被称作实车实时数据。
- **只读监控**：网站不直接下发电机或机械臂控制指令。

## 5. 核心文件与启动入口

以下文件已在 **V12.0.0 压缩包**中核对：

| 文件 | 作用 |
| --- | --- |
| `start_server.sh`、`launcher.py`、`server.py` | 网站启动、HTTP 服务与接口 |
| `web/` | 网页 UI、地图、规划算法、ROS2 图层和静态资源 |
| `start_ros_visualization.sh`、`ros2_visualization_bridge.py` | Ubuntu 订阅 ROS2 并向网页转发（也转发 `/odom`） |
| `start_ros_bridge.sh`、`ros2_odom_bridge.py` | 仅 `/odom` 的旧版桥接，通常**不与可视化桥接同时运行**，避免重复转发 |
| `openmv_camera_usb_main.py`、`openmv_usb_sender.py` | OpenMV JPEG 采集示例和 USB 图像接收/上传 |
| `pi5_camera_sender.py` | 树莓派 5 CSI 图像采集并上传 |
| `start_native_rviz.sh`、`rviz_profiles/` | 启动原生 RViz2 配置作为可视化补充 |
| `data/` | 共享场景数据、摄像头密钥等运行数据 |

网页的 RViz 风格显示主要复现**二维**导航图层，不能完全代替原生 RViz2 的 3D RobotModel、PointCloud2 和任意插件。

## 6. 启动与访问

### 6.1 启动网页服务器（Ubuntu 终端 1）

```bash
car
```

如 `car` 快捷命令尚未生效，可直接运行：

```bash
bash /home/tao/Desktop/car/sim2real/start_server.sh
```

- Ubuntu 本机：`http://127.0.0.1:8080/`
- 同一可互访局域网中的其他设备：`http://<UBUNTU_LAN_IP>:8080/`
- 在服务器终端按 `Ctrl+C` 结束服务。

### 6.2 启动 ROS2 → 网页可视化桥接（Ubuntu 终端 2）

先确保树莓派/Ubuntu 上已经有相关 ROS2 节点发布消息，并且两端 ROS2 DDS 能互通：

```bash
source /opt/ros/humble/setup.bash
cd /home/tao/Desktop/car/sim2real
bash start_ros_visualization.sh
```

**注意：** `car` 只启动网站，不会自动启动 STM32 驱动、雷达驱动、ROS2 桥接、SLAM 或 Nav2。若当前仍未接入 ROS2 底盘，网页可以使用模拟模式。

### 6.3 局域网 ROS2 配置要点

树莓派 5 和 Ubuntu 应满足：

1. 两端网络 IP 可以互访，并允许 DDS 所需的发现与数据通信。
2. `ROS_DOMAIN_ID` 相同，ROS2 发行版和 RMW 实现兼容。
3. 禁止将多机通信限制到 `localhost`；不能把树莓派的 `127.0.0.1` 当作 Ubuntu IP。
4. Ubuntu 能实际订阅 Pi5 发布的 `/scan`、`/odom`；数据话题存在和真实更新是两项不同检查。

### 6.4 验证命令（Ubuntu）

```bash
# ROS2 话题
source /opt/ros/humble/setup.bash
ros2 topic list -t
ros2 topic echo /odom --once
# 接入雷达以后再检查：
ros2 topic hz /scan

# 网页服务器接口
curl -s http://127.0.0.1:8080/api/build
curl -s http://127.0.0.1:8080/api/telemetry
curl -s http://127.0.0.1:8080/api/ros/state
curl -s http://127.0.0.1:8080/api/cameras
```

网站若返回在线状态，只表示近期收到了对应数据；还要核对数据 `source`、真实运动和摄像头画面，排除测试/回放数据。

## 7. 目前完成情况与后续开发计划

| 子系统 | 当前状态 |
| --- | --- |
| 模拟地图、25 格、障碍物、路径规划、物料流程 | **网页软件已实现** |
| 模拟 / 实车模式切换、设置目录 | **网页软件已实现** |
| ROS2 `/odom`、`/scan`、地图/路径的网页接收与二维显示 | **桥接和界面代码已实现；未完成本车硬件联调** |
| 双摄像头 HTTP 图像接收和网页展示 | **示例程序与接口已实现；未完成本车硬件联调** |
| STM32F4 → 树莓派串口解析 → `/odom` | **待根据现有固件协议开发/对接** |
| OpenMV 现有识别功能与 JPEG/识别结果上传融合 | **待开发与联调** |
| 雷达驱动、TF、SLAM、Nav2 的整车接入 | **后续阶段；当前暂不使用雷达** |
| 网页对电机/夹爪下发控制 | **不在当前只读监控范围内** |

建议按以下顺序逐步实现：

1. **ROS2 网络**：让树莓派 5 与 Ubuntu 的 DDS 话题互相可见。
2. **底盘反馈**：打通 STM32F4 → Pi5 串口 → `/odom` → Ubuntu → 网页。
3. **双摄像头**：接入 OpenMV 和 77° CSI 摄像头的视频，并与原有视觉识别程序共存。
4. **视觉任务信息**：把扫码结果、颜色识别和机构动作状态转为 ROS2/网页结构化数据。
5. **雷达与定位（后续）**：接入 `/scan`、TF 和定位，继续验证 Nav2 规划与真实路径的偏差。
6. **实车验收**：校准坐标系、时间戳、通信中断处理和各项安全限制。

## 8. 项目原则

- **设计按理想装置，开发按真实硬件进度实施。**
- 模拟数据、CSV 回放、真实 ROS2 反馈必须有清楚的数据源标识。
- STM32F4 保留底盘运动安全控制和通信超时保护；网页默认只观察，不遥控小车。
- 团队共享场景和摄像头画面仅在可信网络开放，上传密钥不得放进公开仓库。
- 与比赛规则冲突的实验选项应明确标注，正式运行以现场规则和实测场地为准。
