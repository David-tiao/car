# 校赛联调 · OpenMV H7 Plus 和 STM32F4

这条分支用 `algorithm/openmv/openmv_all` 的四个文件和同分支的 `STM32F4/MDK-ARM/GongChuangSai.uvprojx` 配对。两端通过 USART3、115200、8N1 交换 V4 帧。PC 或树莓派不参与发车、抓取或计数。

## 按规则试第一件料

以 `156+123+516+231` 为例。长按选择抽签启停区，等 IMU 预热，短按启动。相机扫码后屏幕应显示四组数字。第一步的目标是红料。红料停在抓取位且指定车槽确认为空，主控才启动夹爪。夹爪复位后，红料必须出现在正确的车槽，屏幕的 P 才从 0 变为 1。故意让这个车槽保持空，车应继续等待。相机超时或接线断开应能停止流程。

| 规则与动作 | 怎么看结果 |
|---|---|
| 规则第 7–8 页，每次抓一件，物料放到车上后才能抓下一件 | 第一批按红、黑、浅蓝上车，P 依次为 1、2、3。转盘一批只做一次初始锁盘，第二、三件继续用盘沿和新的物块观测。 |
| 两批均要在粗加工区按任务码放下，再依次取回 | 第一批落在 1、2、3 号环，第二批按黑、红、浅蓝落在 2、3、1 号环。放置前查料和空环，放置后查空槽和目标环上的料。取回时检查相反的变化。 |
| 第二批暂存区只在正确的同色底料上码垛 | 第一批存放后，第二批黑、红、浅蓝分别叠在 2、1、3 号位。先看一层同色底料，之后检查二层高度对应的视窗和已空的车槽。 |
| 返回抽签启停区并核对显示 | 回程最后一个位置目标为本次发车的原点和朝向，停车后再检查蓝区。完整成功应显示 P12 D12，D 包含三次码垛。压线、整车是否入区、码垛是否稳和环外圈实际可见情况需现场验收。 |

## 哪些数要在车上量

| 文件及参数 | 填写方法和停机原因 |
|---|---|
| `openmv_all/config.py` 的 `TRAY_WINDOWS`、`TRAY_EMPTY_LAB` | 用最终安装角度打开 OpenMV IDE，画面固定 320×240。按实际抓取和放置的前、后姿态记录三个**车槽**的中心和半窗宽，填 (u, v, r)。若个别步骤的盘角不同，用 `TRAY_STEP_WINDOWS[(步号, B或A)]` 单独覆盖。空槽中央选择一块会被料遮住、和六种料分得开的底色，测 LAB 六元组。窗口须只包括该槽，排除转盘上的料。看不见车槽需调整视角或另接到位传感器。缺标定会报 `CAL_TRAY`。 |
| 同文件 `PICK_TARGET_X/Y`、`RING_TARGET_X/Y`、`MATERIAL_THRESHOLDS`、`COVERED_WINDOWS` | 在最终照明下，让抓爪对正实际物料或环心，从 IDE 读像素。六色分别拍样，特别检查黑料与黑印刷圈、蓝料与浅蓝料。数字被盖住时，用可重复的停车姿态测对应环的视窗。偏出抓取容差时相机会等待。 |
| 同文件 `STACK_WINDOWS` | 在每个暂存环以固定斜视姿态分别放一层和两层同色料，记录顶面完整可见的视窗。两窗须能分开。若正上方看到的两个顶面重合，当前相机姿态无法独立判层。 |
| `STM32F4/Config/race_config.h` 的 `RACE_TAUGHT_ROUTES` | 每行是一处停车点，格式为 `{启停区号, 路段号, 环号, x米, y米, yaw弧度}`。原点、朝向取该启停区的实际发车姿态，按行顺序走。为两处启停区分别录入。1 原料到粗加工；2 粗加工到暂存；3 暂存到原料；4 暂存返回；5 和 6 分别是粗加工及暂存的 1~3 号环。跨区路段环号填 0。用拐点让整个车体始终留在灰道内，核对从任意一个环离开都能到下一路线的首个点。缺路段时屏幕显示 `TEACH STATION ROUTE`。 |
| 同一路线表的路段 7、8 | 二维码板和转盘有摆位误差。7 的最后一点是能扫码的停车位，8 的最后一点是原料抓取停车位。当一区同时填写这两段，会替代该区原有的固定扫码路线。两段都空时沿用仓内原路线。 |
| 同文件 `RACE_RING_J00/J01/J10/J11_PX_PER_M` | 在同一环前，分别让车沿自身 x、y 方向小移已知距离，记录环心像素变化，按现有圆环模块的轴向和符号标定雅可比矩阵。矩阵有效时，平放前自动用 `ALIGN` 微调；全零时只依赖已示教的停车位和像素确认。 |
| 同文件 `RACE_STACK_EXTRA_STEPS` | 从平放释放高度升至能平稳叠上第二层的释放高度，记录两者升降的脉冲差，填正数。第二层少下这段，回零时补足。它必须小于原有放置下降行程。升降是相对步数，每次上电按原机械流程建立零点。 |
| `openmv_all/config.py` 的 `HOME_WINDOWS` | 从两个启停区的整车停稳姿态分别取图，选择应该被蓝地面填满、排除随车蓝色物料的视窗。第 25 步末字段用抽签区号 1 或 2，位置由原点里程计和该视窗共同确认。 |
| `LCD_WIDTH/HEIGHT` 和实际车顶屏 | 将四组任务码和抓放次数在车顶点亮，用尺量发光数字实际高度。规则第 2 页要求至少 12 mm。软件根据像素选字号，验收取决于实物屏、字体和遮挡。 |

灰道路点是里程计目标。固定点和到站视觉检查无法绕开突然挡路的黑柱。Gazebo 中的雷达封路和绕行只在仿真路径生效。本分支没有把仿真雷达接到两板实车的行驶中。实测先跑单次抓取，再跑一整批，最后换启停区和障碍布局跑计时全程。

## 两块板传什么

`CHECK,会话,步骤,B或A,颜色,环号` 由 STM32 发出。两个程序分别根据扫码结果推导步骤，必须一致。B 是动作前，A 是动作后。OpenMV 连续多帧确认后回复 `CAN,会话,步骤` 或 `DID,会话,步骤`。重复 DID 只推进一次，超时停在本件。前 24 步是抓放，第 25 步是停车。屏幕 P 是已确认抓取数，D 是已确认放置数。以下保留的是扫码、单项 JOB 与上游开发版的联调参考。

## 装到相机

把相机目录中的 `main.py`、`config.py`、`serial.py`、`tools.py` 一起复制到 OpenMV 启动盘根目录。默认配置已对接 `architecture-v2` 电控。[上板文件](../openmv_all/)

OpenMV P4（TX）接 STM32 PD9（RX），P5（RX）接 PD8（TX），两板共地。双方使用 UART3、115200、8N1。上电后相机发 `READY,IDLE`。下表给出消息正文。实际上线时，收发层自动封装为 `@SEQ,LEN,BODY*XX\n`。LEN 为正文字节数，XX 为从 SEQ 到 BODY 末尾所有 ASCII 字节的异或。例子 `@1,9,ALIGN,2,7*40\n` 最后一个字节为 LF。

## 串口助手和电控该看到什么

| 流程 | STM32 发 | 相机回 | 怎样判定完成 |
|---|---|---|---|
| 扫码 | 裸 `R` 后跟有校验的 `JOB,1,23` | `ACK,JOB,1`，确认读码后重复发 `QR,156+123+516+231,23` | STM32 回 `ACK,QR,23`，相机发 `DONE,QR`、`IDLE`。会话号 0 兼容 `JOB,1` 和不带会话号的 QR。 |
| 数字环 | `ALIGN,2,7` | `ACK,ALIGN,2,7`，识别到对应圆环后发 `POS,RING,2,dx,dy,cx,cy,7,0` | 电控停稳发 `STEP_DONE,0,1`，原地复测则用末位 0。相机按下一步号给新坐标。达到条件后，电控发 `ARRIVED,RING,2,dx,dy,7,count`，相机回 `IDLE`。 |
| 原料区 | `JOB,40` | `ACK,JOB,40`，确认盘几何后发 `AREA_OK,cx,cy,r`、`IDLE` | 三个量都用像素；电控据此计算第一次纠偏。 |
| 物块对准 | 区域确认后发 `JOB,41`，也可用 `JOB,41,tol_x,tol_y` | `ACK,JOB,41`，目标稳定且偏离时发 `POS,MATERIAL,0,dx,dy,cx,cy`，进入容差时发 `ARRIVED,MATERIAL,0,dx,dy`、`IDLE` | 字段 0 是电控解析器要求的目标值。坐标来自抓取位的实际物块。对准完成与夹爪抓取成功是两个事件。 |
| 中止与复位 | `CANCEL` 或 `RESET` | `IDLE` | 停止本轮观测；复位还清除任务码。 |
| 状态查询 | `STATUS` | 空闲时回 `READY,IDLE`；忙时回 `STATUS,当前视觉任务` | 电控使用 READY 建立就绪状态，忙时 STATUS 供观察。 |

圆环偏差以画面中的 (160,120) 为目标。物块沿用你们的 `PICK_TARGET_X/Y=(160,190)`，默认抓取容差为 12 像素，需要按实车夹爪位置核对。首次找盘仍需三个不同颜色物块和盘面几何。

## 和电控同学一起核对的两处

1. `JOB,40` 的 `AREA_OK` 和 `IDLE` 是两帧。相机连续写出两帧，串口仍可能分两次交给电控主循环。主机测试复现了只收到第一帧时，电控已取得有效区域，但 `Vision_StartJob(41)` 会返回 0。建议电控在区域已确认后等待 `VISION_IDLE`，再从主循环下发 41；无需靠固定延时猜测。该分支原料区功能默认 `RACE_MATERIAL_ALIGN_ENABLE=0`，相机姿态、夹爪目标及纠偏矩阵另有实车标定配置。[任务切换](https://github.com/Wangdachang888/GongChuangSai/blob/1da165ccc48b3a7d4f15743a5b2a6660b77226dc/App/app_race.c#L293-L313) · [电控配置](https://github.com/Wangdachang888/GongChuangSai/blob/1da165ccc48b3a7d4f15743a5b2a6660b77226dc/Config/race_config.h#L37-L114)
2. 电控底层允许发送 11～16、21～23、31、32、42 等通用 JOB 编号，但本次核对的比赛调用链对接的是扫码、40、41 和单独的 ALIGN。这个四文件版在 V4 模式下对其余 JOB 回 `ERR,UNSUPPORTED_JOB`。尤其是 42，当前比赛代码没有可供核对的自动抓取请求与成功/失败回执闭环。原视觉算法和旧 V5 的取放流程保留在 V5 模式。
