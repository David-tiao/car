# 工创赛 V5 精简版：**第一批原料区按序夹取**

这份是对 `OpenMV_STM32_固定工位按序夹取_V4.zip` 的精简补丁，不是完整 Keil 工程；必须与原 STM32 `GongChuangSai (6).zip` 合用。保留已实现的底盘、IMU、OLED、舵机、步进电机驱动，不重写它们。

## 仅保留当前实际能接通的流程

1. STM32 选择启停区 → 按既有路线到二维码板，向 OpenMV 发送 `R`。
2. OpenMV 连续确认二维码四组任务，LCD 显示完整任务，通过 `#SEQ` 发送至 STM32。
3. STM32 按既有路线前往原料区；OpenMV 根据三个不同颜色物料的 120° 布局及白色盘面/外缘首次锁定转盘，发 `#DISK` 和固定夹取工位 `#SLOT`。
4. STM32 以视觉工位像素为依据判断对齐。如果误差超出容差，**只有真正完成像素→车身位移标定后才允许自动移动**；否则进入安全故障，**绝不盲动**。
5. 底盘对齐停稳后，STM32 发 `#ARM,1`，OpenMV 应答 `#ARM_OK,1`。OpenMV **只**在二维码本次需要的颜色进入固定工位并保持静止时发送 `#OBJ`。
6. STM32 发 `#ARM,0`，启动 `PickFsm_StartSingle(slot=0/1/2)`，并反复发送 `#TAKE` 直到收到 `#TAKE_OK`，防止机械手遮挡令 OpenMV重新触发。
7. 机械状态机完成一件后，STM32 发送单字节 `K`；OpenMV 只在已收到 `#TAKE` 的等待状态推进到下一件。**每次机械动作只抓一件，不跳颜色**。
8. 三件完成后 STM32 发 `#GROUP_DONE,1`，OpenMV 刷新 LCD，双方停在第一批完成状态。**不会自动去粗加工区或执行后续三组**。

## 对 V4 具体删掉了什么

- OpenMV：删除尚未在本阶段使用的数字环/OCR、蓝框、黑线识别，`RING` / `EDGE` / `BLUE` 模式，`#TRK` / `#LOST` 高频连续上报，以及相关的配置、超时与分支；不再假装完成第二至第四组。
- STM32：删除比赛主流程与独立夹取按键测试的双分支；合并二维码/视觉事件两套串口逐字节收包的重复逻辑；合并重复的 `#TAKE` 重发逻辑；保留现有 34 个任务的计划器，因为日志、任务序号和后续开发仍有引用，不在这次破坏其他模块的接口。
- **没有删掉**：白盘真实性验证、仅在原盘附近重新锁定（支持剩余两件/一件）、颜色跟踪停稳判定、UART 字段校验、确认/重试、夹爪状态机、安全停止和实机标定互锁。

OpenMV `main.py + utils.py + config.py` 合计从 V4 的 **2402 行**缩为 V5 的 **1053 行**，约减少 **56%**。STM32 不重写成熟机械状态机，避免为少几行牺牲动作安全性。

## 替换方法

1. **先备份**原始工程和 OpenMV 文件系统。
2. 把 `STM32/Hardware/` 下全部同名文件复制到原 `GongChuangSai/Hardware/`（其他原文件保持不变）。不需要再往 Keil 工程里添加新的 `.c` 文件。
3. 把 `OpenMV/main.py`、`utils.py`、`config.py` 放入 OpenMV 文件系统根目录。
4. **不要把 STM32 `.c/.h`、测试脚本或 PC 校准脚本拷到 OpenMV 上。**
5. 编译之前核对原工程的 `APP_RUN_MODE = APP_MODE_RACE`，保留现有定时器、中断、四轮电机及外设初始化。

## 必须实机检查的四项参数

- OpenMV `config.py`：`PICK_DIRECTION_X/Y`（图像中夹爪所在方向）、`PICK_TARGET_X/Y`（固定工位正确对齐时的像素位置）。当前的 `(160,350)` 与 `(160,190)` 都是**待验证初值**，不能保证任意安装角度可用。
- STM32 `race_config.h`：`RACE_ALIGN_TARGET_X/Y_PX` 必须与上面 `PICK_TARGET_X/Y` 一致；`RACE_ALIGN_CALIBRATED` 默认是 **0**，因此超差时停车/报配置错误，不会自动微调。
- 若需要自动微调，必须用安全的实测标定填入 `RACE_ALIGN_M_PER_PX_XX/XY/YX/YY`，验证正负方向、0.04m 单步限制和 0.18m 总位移限制后，才把 `RACE_ALIGN_CALIBRATED` 设为 1。
- 机械存料盘 slot 0/1/2 分别对应的旋转角度、夹爪的前后安全间隙、单次升降行程都必须空载确认。**程序通过并不等于机械实物能够无干涉运行**。

## 已通过的本地测试（不是实机验收）

- GCC `-std=c99 -Wall -Wextra -Werror`：视觉协议、UART、路线、`app_race.c` 及 `app_pick_fsm.c` 代码可移植编译检查。
- OpenMV 三个 Python 文件 CPython 语法检查。
- 颜色顺序、重复 K、防跳件、串口拆包与非法包过滤、缺料转盘重锁、三件完成后停车的模拟测试。
- **未验证**：完整 Keil 目标编译；OpenMV 5.x 实际摄像头 API；车身相机标定和现场光照；舵机/步进机构机械干涉；后面三组比赛任务。

如果这版的单件夹取尚未经过实物验收，建议先架空车轮、固定转盘、无载运行，然后逐步验证同一颜色顺序的三件夹取。
