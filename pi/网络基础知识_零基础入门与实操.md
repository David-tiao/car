## 0. 开始前的约定

本教程主要使用下面几种环境：

- **Windows**：打开 PowerShell 或 Windows Terminal。
- **macOS**：打开「终端（Terminal）」。
- **Linux**：打开终端；示例以 Ubuntu/Debian 类系统为主。
- **Windows 想练 Bash**：推荐安装 **WSL（Windows Subsystem for Linux，适用于 Linux 的 Windows 子系统）**。Windows 上的 Git Bash 也能运行很多 Bash 命令，但不完全等于 Linux。

**命令约定：**

- 代码框中的命令不包含终端提示符 `$` 或 `>`，可以直接复制。
- `YOUR_USERNAME`、`SERVER_IP`、`PORT` 等是**占位符**，执行前要换成自己的实际信息。
- `example.com` 是用于文档演示的域名；`192.168.1.20` 是局域网示例 IP，不代表你的真实设备。
- 不要执行来源不明的脚本，不要随意使用 `sudo`、管理员权限或关闭防火墙。

## 1. 学习前先建立一张网络知识地图

### 1.1 通俗理解

把网络想象成**寄快递**：

- **电脑/手机**：寄件人或收件人。
- **IP 地址**：收件地址，告诉网络把数据送到哪台设备。
- **端口（Port）**：具体收件窗口，告诉设备把数据交给哪个程序。
- **域名（Domain）**：方便记忆的名称，例如 `example.com`。
- **DNS**：通讯录，把域名查成 IP 地址。
- **路由器（Router）**：决定快递下一站往哪走。
- **协议（Protocol）**：双方商定的交流规则。
- **数据包（Packet）**：拆分成一小份一小份发送的数据。

例如浏览器访问 `https://example.com`，可以简化成：

```text
输入网址
   ↓
DNS 查询：example.com 对应哪个 IP？
   ↓
建立网络连接（通常是 TCP；HTTP/3 使用 QUIC/UDP）
   ↓
TLS 安全握手：确认对方身份，建立加密通信
   ↓
发送 HTTP 请求
   ↓
服务器返回网页内容
   ↓
浏览器显示网页
```

### 1.2 必须分清的三个地址

| 概念 | 示例 | 用途 |
| --- | --- | --- |
| 域名 | `example.com` | 方便人记忆的网站名称 |
| IP 地址 | `192.168.1.20` | 定位网络中的设备或网络接口 |
| IP + 端口 | `192.168.1.20:22` | 定位某个地址上的服务，例如 SSH |

常见端口：`22`（SSH）、`80`（HTTP）、`443`（HTTPS）、`5900`（常见 VNC 默认显示端口）。这些只是惯例，具体服务可以修改端口。

> **记忆**：IP 决定「找哪台设备」，端口决定「找设备里的哪个服务」。

## 2. 操作系统：Windows、macOS、Linux 有什么区别

### 2.1 通俗理解

**操作系统（Operating System，OS）** 就像公司的总管：负责管理硬件、运行软件、保存文件、分配内存，以及控制用户权限。不同操作系统像不同的工作环境：工具、习惯和擅长领域不一样。

### 2.2 主要类型与适用工作

| 操作系统 | 通俗特点 | 常见适用场景 | 需要了解的限制 |
| --- | --- | --- | --- |
| **Windows** | 兼容大量桌面软件 | 日常办公、游戏、企业应用、部分开发 | 一些 Linux 命令不能直接在 PowerShell 中照搬 |
| **macOS** | 桌面体验与 Unix 工具兼顾 | 软件开发、设计、音视频制作、办公 | 依赖 Apple 硬件与其生态，部分 Windows 软件不能原生运行 |
| **Linux** | 灵活、可定制、常见于服务器 | Web 服务、云计算、运维、容器、开发 | 初学者需要逐步熟悉终端与权限 |
| **Android** | 面向移动设备的操作系统 | 智能手机、平板、部分嵌入式设备 | 虽使用 Linux 内核，但不是普通桌面 Linux 发行版 |
| **iOS / iPadOS** | Apple 移动设备系统 | 手机、平板及移动 App | 系统权限与软件分发相对受限制 |

**专业名词补充：**

- **内核（Kernel）**：负责进程、内存、设备和系统调用等底层工作。
- **Linux 发行版（Distribution）**：基于 Linux 内核组合的软件系统，例如 Ubuntu、Debian、Fedora。
- **命令行界面（CLI）**：通过输入命令操作计算机。
- **图形界面（GUI）**：通过窗口、图标、鼠标操作计算机。
- **服务器（Server）**：提供服务的设备或程序；不是一种独立的操作系统。
- **虚拟机（VM）**：模拟一整套计算机环境；**容器（Container）** 通常共享宿主机内核，不能简单当成完整虚拟机。

### 2.3 为什么服务器经常用 Linux？

很多 Linux 系统适合通过 SSH 远程管理，可以按需安装服务、编写自动化脚本，并且广泛用于云服务器与容器环境。但这不意味着 Windows 或 macOS 不能提供服务器功能。

### 2.4 必会操作：认识当前系统

**Windows PowerShell：**

```powershell
whoami           # 当前用户名
Get-Location     # 当前所在目录
Get-ComputerInfo # 系统信息，输出比较长
ipconfig         # 查看网络配置
```

**Linux：**

```bash
whoami              # 当前用户名
pwd                 # 当前目录
uname -a            # 内核与硬件概要
cat /etc/os-release # 发行版信息
ip addr             # 网络地址；部分精简系统需要安装 iproute2
```

**macOS：**

```bash
whoami     # 当前用户名
pwd        # 当前目录
sw_vers    # macOS 版本
uname -m   # CPU 架构，例如 arm64 或 x86_64
```

**小练习：**说出你电脑的操作系统、当前用户名、CPU 架构，以及它适合做哪些工作。

## 3. 文件格式：后缀、可执行文件与跨系统兼容

### 3.1 通俗理解

文件后缀像「包装上的标签」：`.jpg` 表示它通常是图片，`.pdf` 表示它通常是文档。但**标签不等于文件的真实内容**：把 `photo.jpg` 改名为 `photo.exe`，不会自动让图片变成程序。

### 3.2 常见文件后缀速查

| 文件后缀 | 大致含义 | 常见用途/平台 |
| --- | --- | --- |
| `.txt` | 纯文本 | 各系统均可打开 |
| `.md` | Markdown 文本 | 笔记、文档、GitHub README |
| `.pdf` | 固定版式文档 | 跨平台阅读 |
| `.jpg` / `.png` / `.webp` | 图片 | 跨平台图片格式 |
| `.mp4` / `.mp3` | 媒体文件 | 视频 / 音频 |
| `.zip` / `.7z` | 压缩文件 | 打包和传输 |
| `.tar.gz` | tar 归档后再用 gzip 压缩 | Linux/macOS 常见 |
| `.exe` | Windows 可执行程序 | 通常不能在 Linux/macOS 直接原生运行 |
| `.msi` | Windows 安装包 | Windows 安装程序 |
| `.bat` / `.cmd` | Windows 批处理脚本 | CMD 命令环境 |
| `.ps1` | PowerShell 脚本 | PowerShell，跨平台能力取决于脚本内容 |
| `.sh` | Shell 脚本（常见为 Bash） | Linux/macOS/WSL 等 |
| `.py` | Python 源代码 | 需要合适的 Python 运行环境 |
| `.js` | JavaScript 源代码 | 浏览器或 Node.js 等运行环境 |
| `.jar` | Java 归档文件 | 部分可以通过 Java 运行 |
| `.app` | macOS 应用程序包 | macOS 中通常表现为一个应用图标 |
| `.dmg` / `.pkg` | macOS 磁盘映像 / 安装包 | macOS |
| `.deb` / `.rpm` | Linux 软件包 | 不同 Linux 发行版的软件包格式 |
| `.AppImage` | Linux 便携应用格式 | 部分 Linux 桌面环境 |
| `.dll` / `.so` / `.dylib` | 动态链接库 | 常见于 Windows / Linux / macOS |
| `.json` / `.yaml` / `.yml` | 结构化配置或数据 | API、应用配置、自动化 |

### 3.3 什么是「可执行文件」？

可执行不是单靠后缀判断的，还涉及**文件内部格式、解释器、运行权限和 CPU 架构**。

- Windows 原生程序常见为 **PE 格式**（例如 `.exe`）。
- Linux 原生程序常见为 **ELF 格式**，**可以没有扩展名**。
- macOS 原生程序常见为 **Mach-O 格式**，应用还常包装为 `.app`。
- `.sh`、`.py` 往往是**脚本**：需要 Bash、Python 等解释器。
- `x86_64` 和 `ARM64` 是不同 CPU 架构；系统相同也不代表二进制程序一定兼容。

**通俗记忆**：脚本像「菜谱」，解释器像「厨师」，CPU/操作系统像「厨房设备」。菜谱写对了，还要有合适的厨师和设备。

### 3.4 必会操作：查看、运行文件

**Linux/macOS：**

```bash
ls -lah              # 查看文件、大小、权限（部分显示格式因系统不同）
file README.md        # 根据内容判断文件类型
cat README.md         # 输出文本内容
bash hello.sh         # 通过 Bash 解释器运行脚本
chmod +x hello.sh     # 为脚本增加执行权限
./hello.sh            # 从当前目录执行（需有合适解释器/shebang）
```

`chmod +x` 不会把 Windows 的 `.exe` 变成 Linux 原生程序。`./` 代表「当前目录」。

**Windows PowerShell：**

```powershell
Get-ChildItem         # 查看目录内容
Get-Content .\README.md # 读取文本文件
```

Windows 有 PowerShell 脚本执行策略，`.ps1` 不一定能双击或直接运行；**不要为了运行陌生脚本而随意放宽安全策略**。

### 3.5 跨平台常见坑

1. **换行符**：Windows 常见 `CRLF`，Linux/macOS 常见 `LF`；Bash 脚本出现 `^M`、`bad interpreter` 可能与此有关。
2. **路径写法**：Windows 常见 `C:\Users\...`，Linux/macOS 常见 `/home/user/...`。
3. **大小写**：Linux 文件名通常区分大小写；Windows/macOS 的常见默认文件系统配置通常不区分，但不能绝对化。
4. **双后缀欺骗**：`invoice.pdf.exe` 可能其实是程序，下载和执行前务必核对来源与真实类型。

## 4. 网络与 HTTPS：从 ping 到安全访问网站

### 4.1 先理解：浏览网页到底发生了什么？

假设在浏览器输入：

```text
https://example.com
```

这里的 `https` 是通信方案，`example.com` 是域名。访问过程可理解为「查地址 → 建联系 → 验身份并约定加密 → 发请求 → 收响应」。

### 4.2 认识五个关键协议

| 术语 | 通俗比喻 | 专业含义 |
| --- | --- | --- |
| **DNS** | 查通讯录 | 域名解析系统，返回 IP 等记录 |
| **IP** | 地址系统 | 负责网络寻址与数据包转发 |
| **ICMP** | 测试对方有没有回应 | 网络控制与诊断协议，`ping` 常用它 |
| **TCP** | 有确认、按序交付的运输方式 | 面向连接、可靠的字节流传输协议 |
| **UDP** | 更轻量的投递方式 | 无连接的数据报传输协议，本身不保证可靠交付 |
| **HTTP** | 交流网页内容的格式 | 超文本传输协议，请求和响应应用层协议 |
| **TLS** | 加密及验明身份的过程 | 传输层安全协议，HTTPS 通常通过它保护 HTTP |

### 4.3 HTTPS 握手到底是什么？

**HTTPS = HTTP + TLS 安全保护**（实际协议栈因 HTTP 版本而异）。先看经典的 **HTTP/1.1 或 HTTP/2 通过 TCP** 的简化流程：

```text
浏览器                         网站服务器
  |                                 |
  |-- DNS：查找网站 IP（可能由系统/缓存完成）
  |                                 |
  |-- SYN ------------------------->|  TCP 第一次握手
  |<---------------------- SYN+ACK --|  TCP 第二次握手
  |-- ACK ------------------------->|  TCP 第三次握手
  |                                 |
  |-- ClientHello ----------------->|  TLS：提出版本、算法、密钥协商参数
  |<-- ServerHello、证书等 ---------|  TLS：协商、提供身份信息
  |-- 验证证书并完成密钥协商 --------|  核对域名、证书链、有效期等
  |<====== 加密的 HTTP 数据 =======>|  发送请求、接收网页
```

**必须记住：**

- **TCP 三次握手**解决的是「先建立可靠连接」。
- **TLS 握手**解决的是「协商安全参数、验证服务器身份、建立加密密钥」。
- 浏览器验证证书，主要为了防止冒充网站的攻击；**有 HTTPS 不代表网站内容一定可信，也不能防止所有钓鱼**。
- 上面是概念图，不是完整报文时序；**TLS 1.3** 具体消息和加密时机会更复杂。
- **HTTP/3** 使用 **QUIC（基于 UDP）**，把 TLS 1.3 握手整合到 QUIC 连接建立中，**不能把所有 HTTPS 都理解为先 TCP 三次握手**。

### 4.4 `ping` 是干什么的？

**通俗理解**：`ping` 像向某个地址喊「有人吗？」，然后看有没有回音、多久收到回复。

**专业理解**：`ping` 通常发送 ICMP Echo Request 并等待 Echo Reply，用来辅助判断**可达性、延迟（latency）和丢包（packet loss）**。

> **关键区别：`ping` 不进行 TCP 三次握手，也不进行 TLS/HTTPS 握手。**
> `ping` 成功，只说明相关 ICMP 通信有响应；**不代表网页的 443 端口一定可用**。`ping` 失败也可能只是对方或中间设备屏蔽了 ICMP。

**Windows PowerShell：**

```powershell
ping -n 4 example.com
nslookup example.com
Test-NetConnection example.com -Port 443
curl.exe -I https://example.com
```

**Linux/macOS：**

```bash
ping -c 4 example.com
nslookup example.com
curl -I https://example.com
```

在 Linux/macOS 上，如果安装了 `nc`，还可以检查 TCP 443 端口：

```bash
nc -vz example.com 443
```

> 如果系统没有 `nslookup`、`nc`、`curl` 等命令，需要安装对应工具；不必为了单个命令修改系统安全设置。

**如何看 `ping` 输出？**

- `time=...ms`：一次往返大概用了多少毫秒，越低通常越快，但受网络路径影响。
- `packet loss` /「丢失」：有多少探测没有得到响应，**不一定都是链路实际丢包**，也可能是设备限制 ICMP。
- `TTL`：IP 数据包的生存时间字段；**不是网速**。

### 4.5 从「网站打不开」开始排查

按顺序检查，比盲目重启有效：

1. **设备联网了吗？** 看 Wi-Fi/网线及本机 IP 地址。
2. **DNS 能查到地址吗？** `nslookup example.com`。
3. **ICMP 有回应吗？** `ping`（仅作辅助，失败不等于断网）。
4. **TCP 443 能连吗？** Windows 用 `Test-NetConnection`，其他系统可用 `nc`。
5. **HTTPS 能访问吗？** `curl -I https://example.com`。
6. **浏览器有证书错误吗？** 检查系统时间、域名是否正确、证书是否可信；不要轻易绕过警告。
7. **是否涉及代理/防火墙/DNS？** 分别检查规则、端口和日志。

想看经过哪些路由节点：

```powershell
# Windows
tracert example.com
```

```bash
# Linux/macOS（有的 Linux 环境需先安装 traceroute）
traceroute example.com
```

路由节点不回应探测是常见现象，不代表那一跳必然坏了。

## 5. 远程连接：SSH 与 VNC

### 5.1 通俗理解

你在自己电脑前，需要操作另一台电脑：

- **SSH**：像打电话让远处的电脑「听命令做事」，主要使用文字终端。
- **VNC**：像远程看到对方电脑桌面，用鼠标和键盘操作图形界面。

### 5.2 SSH 与 VNC 对比

| 项目 | SSH | VNC |
| --- | --- | --- |
| 主要交互方式 | 终端、命令行 | 图形桌面 |
| 常见场景 | 管理 Linux 服务器、执行脚本、传输文件 | 远程操作桌面软件 |
| 常见默认端口 | TCP `22` | TCP `5900` 起，具体视配置而定 |
| 安全性 | 协议本身提供加密与身份验证 | **取决于实现与配置**，不可默认所有 VNC 都具备安全加密 |
| 资源占用 | 通常较小 | 通常较大，依赖画面传输 |

### 5.3 SSH：第一次连接服务器

**前提条件：**

1. 远程设备已开启 **SSH Server（例如 OpenSSH Server）**。
2. 你知道远程设备的 IP、用户名、连接端口。
3. 两台设备网络可达；服务器防火墙允许相应连接。
4. 你有获授权的账号与认证方式。

假设服务器在同一局域网中，地址为 `192.168.1.20`，用户名是 `student`：

```bash
ssh student@192.168.1.20
```

如果 SSH 端口是 `2222`：

```bash
ssh -p 2222 student@192.168.1.20
```

首次连接时，SSH 可能询问是否信任服务器**主机密钥指纹**。应通过管理员或可信渠道核对指纹，不能机械地直接接受。

**在 Ubuntu/Debian 服务器上启用 SSH Server（需设备所有者授权）：**

```bash
sudo apt update
sudo apt install openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh
```

Windows 10/11 通常可使用 OpenSSH 客户端；如果找不到 `ssh`，可在系统「可选功能」中检查 OpenSSH Client。**客户端与服务器端不是一回事**。

### 5.4 SSH 密钥比反复输入密码更适合长期管理

**通俗理解**：公钥像「锁」，私钥像「钥匙」；服务器保存获准使用的公钥，自己保管私钥。

创建密钥（Windows/macOS/Linux 的 OpenSSH 客户端通常支持）：

```bash
ssh-keygen -t ed25519 -C "my-laptop"
```

- **公钥**通常是 `~/.ssh/id_ed25519.pub`，可以放到服务器授权列表。
- **私钥**通常是 `~/.ssh/id_ed25519`，**不要上传、共享或提交到 GitHub**。
- 建议为私钥设置口令（passphrase）。
- 服务器要把公钥写入目标用户的 `~/.ssh/authorized_keys`，同时配置正确权限；具体操作与环境相关。

**复制文件到服务器：**

```bash
scp ./notes.md student@192.168.1.20:~/
```

**常见 SSH 报错：**

| 报错 | 常见原因 | 优先检查 |
| --- | --- | --- |
| `Connection timed out` | 路由不通、防火墙丢弃请求、地址错误 | IP、网络、端口、防火墙 |
| `Connection refused` | 目标可达但对应端口没有服务或被拒绝 | sshd 是否启动、监听端口 |
| `Permission denied` | 用户名、密码或密钥授权不匹配 | 账户、授权公钥、服务端日志 |
| `Host key verification failed` | 主机身份信息变化/不匹配 | **先核实身份**，不要盲目删除安全记录 |

**安全建议**：不要直接将 SSH/VNC 管理端口暴露在公网；优先使用可信 VPN、堡垒机或受控网络访问，并限制访问源、使用密钥和日志审计。

### 5.5 VNC：远程桌面操作流程

以你**拥有管理权限的两台设备**为例：

1. 在被控端安装、配置受信任的 **VNC Server**。
2. 设置访问认证，明确哪些桌面会话允许被共享。
3. 在控制端安装对应的 **VNC Viewer**。
4. 确认两台设备可通过局域网或可信安全隧道互访。
5. 在 Viewer 中填写被控端地址和端口（例如 `192.168.1.20:5900`；不同软件的地址写法可能不同）。
6. 验证连接是否加密；不确定时，**通过 SSH 隧道或可信 VPN 保护 VNC 流量**。

**可选：通过 SSH 隧道连接只监听本机的 VNC 服务**（假设 VNC 在远端 `127.0.0.1:5900`）：

```bash
ssh -L 5901:127.0.0.1:5900 student@192.168.1.20
```

保持 SSH 窗口运行，在本机 VNC Viewer 连接 `127.0.0.1:5901`。此示例需要远端 VNC Server 事先安装好并正确监听；它**不会自动启动 VNC 服务**。

> Windows 自带的 **RDP（远程桌面协议）** 与 VNC 是不同协议，不能仅因为都能控制桌面就认为它们互通。

## 6. Clash 代理：理解代理、防火墙与 VPN

### 6.1 通俗理解

- **代理（Proxy）**：你不直接去某个网站，而是让一个「中间人服务」替你发起部分请求。
- **VPN**：在设备与指定网络/服务之间建立受保护的网络隧道，具体能覆盖哪些流量取决于路由和配置。
- **防火墙（Firewall）**：像门卫，根据规则判断某些网络连接能否进出。
- **Clash 类客户端**：根据配置，把接收到的网络流量分配为直连、代理或其他处理方式。**客户端本身不自动提供可用的远程代理服务器**。

**三者不能画等号**：代理决定「谁代发请求」，VPN 关注「隧道与网络路由」，防火墙关注「是否允许通信」。

### 6.2 Clash 类客户端的两组关键设置

**第一组：流量怎样进入代理程序？**

| 方式 | 通俗理解 | 注意 |
| --- | --- | --- |
| **系统代理（System Proxy）** | 告诉遵循系统设置的软件「请找本机代理程序」 | 不是所有应用都遵守；普通 ICMP `ping` 通常不会经过 HTTP/SOCKS 代理 |
| **TUN 模式** | 建立虚拟网络接口，通过路由把更多程序的流量交给代理程序 | 可能需要较高权限；能否覆盖全部流量、DNS、UDP 取决于具体实现和配置 |

**第二组：进入代理程序的流量怎样出去？**

| 路由模式 | 含义 |
| --- | --- |
| **Rule（规则）** | 按规则判断直连、代理或其他处理策略 |
| **Global（全局）** | 进入代理内核的流量统一交给指定的全局策略；**并不自动让所有应用都进入代理内核** |
| **Direct（直连）** | 进入代理内核的流量按直连处理 |

> **容易混淆**：开启「全局模式」不等于电脑里的每一个程序都一定通过代理；还要看有没有开启系统代理/TUN，以及程序是否遵守这些入口设置。

### 6.3 常见概念

- **节点（Node）**：一个可选的代理服务器/出口。
- **订阅（Subscription）**：客户端获取配置、节点、规则的一种方式；订阅地址可能包含密钥或账号信息。
- **HTTP 代理 / SOCKS5**：两类常见代理协议，支持能力与使用方法不同。
- **规则分流**：按照域名、IP、进程或其他匹配条件决定连接路径。
- **DNS 泄漏**：本应通过指定受保护路径处理的域名查询，意外通过其他 DNS 路径暴露；是否发生要结合实际 DNS 配置检查。

### 6.4 必会操作：观察代理是否生效

以下是**通用操作逻辑**，不同 Clash/Mihomo 图形客户端名称略有区别：

1. 使用可信来源安装客户端，并确认配置文件或订阅的来源。
2. 导入**你有权使用**的配置，选择合适的节点/策略。
3. 选择 Rule、Global 或 Direct，理解三者差异。
4. 在需要代理浏览器等应用时启用「系统代理」。
5. 如某个应用不遵守系统代理且你确实需要接管它的流量，再评估 TUN 模式。
6. 查看客户端「连接/日志」页，确认请求最终是直连还是经过代理。
7. 排错时逐个切换设置，记录现象，结束后恢复原配置。

如果客户端提供了本机 HTTP 代理监听端口，可显式让 `curl` 使用代理。**端口必须以自己客户端实际显示的数值为准**：

```bash
curl -x http://127.0.0.1:PORT -I https://example.com
```

这里的 `127.0.0.1` 是「本机回环地址」，不是外网服务器地址。示例中的 `PORT` 需要替换成实际端口号。

**提醒：**普通 `ping` 不一定走代理；用 `ping` 结果判断 Clash 是否生效，往往会误判。应检查实际应用请求、代理日志与出口信息。

### 6.5 防火墙的基本逻辑

把防火墙规则理解成：

```text
来源地址 + 目标地址 + 协议 + 端口 + 方向 → 允许 / 拒绝
```

例子：允许某个可信局域网的设备访问 SSH 服务器的 TCP `22` 端口，不代表自动允许它访问所有端口。

- **入站（Inbound）**：外部发往本机的连接。
- **出站（Outbound）**：本机发往外部的连接。
- **允许（Allow）/拒绝（Deny）**：防火墙采用的处置方式。

**安全原则**：保持系统防火墙开启；只为必要服务放行必要的来源与端口，不要为了「试试看能不能连上」长期关闭防火墙。

### 6.6 VPN 与代理的区别（不要只记名字）

| 维度 | 常见应用代理 | 常见 VPN |
| --- | --- | --- |
| 工作范围 | 通常是应用或支持代理协议的流量 | 常通过虚拟网卡和路由覆盖部分或大量 IP 流量 |
| 常见目的 | 请求转发、分流 | 远程接入内网、保护传输链路、建立专用网络 |
| 是否自动加密所有流量 | **不一定**，看代理协议与端到端协议 | 隧道内流量通常受隧道协议保护，但覆盖范围取决于配置 |
| 是否保证匿名/安全 | **不保证** | **不保证** |

无论使用哪种方式，都应遵守所在网络、单位和地区的规定，使用合法且可信的服务，不要把代理当成隐私和安全的万能解决方案。

## 7. Bash 脚本：让计算机自动执行任务

### 7.1 通俗理解

平时你输入一行命令，电脑执行一步；把很多命令按顺序写进一个文件，就是**脚本（Script）**。它像一张自动化操作清单。

**Bash** 是一种 Shell（命令解释器），也是一种脚本语言。**终端（Terminal）是输入命令的窗口，Shell 是解释和执行命令的程序**，两者不是同一个概念。

### 7.2 先学常见命令（Linux/macOS/WSL Bash）

```bash
pwd                 # 查看当前目录
ls -la              # 查看目录内容
cd ~/               # 进入用户主目录
mkdir -p demo       # 新建文件夹
cd demo             # 进入文件夹
touch notes.txt     # 创建空文件（若存在则更新修改时间）
echo "hello"         # 输出文本
cat notes.txt       # 查看文本
cp notes.txt copy.txt # 复制文件
mv copy.txt old.txt  # 移动或重命名文件
```

**特别注意**：`rm` 是删除命令，很多时候不会进入回收站；初学阶段先理解文件路径与命令含义，不要复制来源不明的批量删除命令。

### 7.3 写第一个脚本：`hello.sh`

使用编辑器创建 `hello.sh`，写入：

```bash
#!/usr/bin/env bash
# 这是注释，不会执行
name="网络初学者"
echo "你好，$name！"
echo "今天是：$(date +%F)"
```

运行：

```bash
bash hello.sh
```

**逐行解释：**

- `#!/usr/bin/env bash`：shebang，告诉系统如何寻找 Bash 解释器（通过直接执行脚本时生效）。
- `#`：注释。
- `name="..."`：定义变量，等号两侧**不要加空格**。
- `$name`：读取变量。
- `$(...)`：先执行括号里的命令，再使用输出结果。
- `echo`：输出文字。

### 7.4 实战：写一个网络检查脚本

新建 `check_network.sh`，粘贴以下代码（适用于已安装 Bash、`ping` 和 `curl` 的 **Linux/macOS/WSL** 环境）：

```bash
#!/usr/bin/env bash
set -euo pipefail

# 使用方法：bash check_network.sh example.com
host="${1:-example.com}"

echo "=== 检查域名：$host ==="

# ICMP 检查只供参考；对方可能禁 ping
if ping -c 2 "$host"; then
  echo "[ICMP] 收到了 ping 响应"
else
  echo "[ICMP] 没收到响应；不能据此判定 HTTPS 不可用"
fi

# HTTPS 检查：最多等待 10 秒，输出 HTTP 状态码
if curl --head --location --silent --show-error \
  --max-time 10 --output /dev/null \
  --write-out 'HTTP 状态码：%{http_code}\n' "https://$host"; then
  echo "[HTTPS] curl 成功完成请求"
else
  echo "[HTTPS] 请求失败，请继续检查 DNS、端口、证书或代理"
fi
```

运行：

```bash
bash check_network.sh example.com
```

想直接用 `./check_network.sh` 运行：

```bash
chmod +x check_network.sh
./check_network.sh example.com
```

**知识点：**

- `$1`：脚本第一个参数。
- `${1:-example.com}`：如果没传参数，默认使用 `example.com`。
- `if ...; then ... else ... fi`：条件判断。
- `set -euo pipefail`：帮助发现脚本错误；并非适用于所有脚本的万能开关。
- `"$host"`：变量加双引号，避免空格拆分和通配符扩展造成意外。
- `curl` 的成功退出表示本次传输/请求流程成功执行，**不等于 HTTP 状态码一定为 200**；某些状态码如 404 也可能正常收到响应。

### 7.5 你应该会的 Bash 语法

**条件：**

```bash
age=18
if [ "$age" -ge 18 ]; then
  echo "已成年"
else
  echo "未成年"
fi
```

**循环：**

```bash
for item in apple banana orange; do
  echo "水果：$item"
done
```

**函数：**

```bash
say_hello() {
  echo "你好，$1"
}

say_hello "Bash"
```

## 9. GitHub 注册与 Git 版本管理

### 9.1 最容易混淆：Git 不等于 GitHub

**通俗理解：**

- **Git**：本机的「文件历史记录工具」，能记录谁在什么时候改了什么。
- **GitHub**：托管 Git 仓库的在线平台，方便备份、协作、代码审查。

即使断网，你也可以在本地使用 Git 的很多功能；使用 Git 也不一定需要 GitHub。

### 9.2 先认识六个概念

| 名词 | 通俗解释 |
| --- | --- |
| **Repository（仓库）** | 一个由 Git 管理的项目及历史记录 |
| **Working Directory（工作区）** | 正在修改的实际文件 |
| **Staging Area（暂存区）** | 选好准备放入下一次版本记录的改动 |
| **Commit（提交）** | 保存一次可追踪的版本快照 |
| **Branch（分支）** | 一条独立的开发历史线 |
| **Remote（远程仓库）** | 网络上的另一个仓库，例如 GitHub 仓库 |

```text
修改文件（工作区）
       │ git add
       ▼
选择本次要提交的改动（暂存区）
       │ git commit
       ▼
保存到本地 Git 历史记录
       │ git push
       ▼
上传到 GitHub 远程仓库
```

### 9.3 注册 GitHub 账号

1. 打开 [GitHub 官方网站](https://github.com/)。
2. 选择注册（Sign up），按页面提示填写邮箱、用户名、密码等信息。
3. 完成邮箱验证。
4. 建议启用 **2FA（双重身份验证）**，妥善保管恢复方式。
5. 登录后认识个人主页、**Repositories**（仓库）和 **New repository**（新建仓库）入口。

> 网页按钮和具体验证流程可能随产品版本调整，以 GitHub 当前页面提示为准。

### 9.4 安装并配置 Git

安装 Git：[https://git-scm.com/downloads](https://git-scm.com/downloads)

安装后打开终端：

```bash
git --version
```

配置提交身份（将文字替换为自己的信息）：

```bash
git config --global user.name "YOUR_NAME"
git config --global user.email "YOUR_EMAIL@example.com"
```

这里的姓名、邮箱用于 Git **提交记录**，**不等于登录 GitHub**。如果不想公开个人邮箱，可考虑使用 GitHub 提供的隐私邮箱方案。

### 9.5 实战：创建第一个本地 Git 仓库

下面的示例在 **Bash（Linux/macOS/WSL/Git Bash）** 中操作：

### 9.6 把本地项目推送到 GitHub

**先在 GitHub 网页创建一个空仓库**，例如 `network-notes`；为了避免初学者第一次推送冲突，创建时先**不要勾选自动添加 README、.gitignore 或 License**。然后在刚才的本地目录执行：

```bash
git push -u origin main
```

**身份验证说明：**GitHub 已不支持直接使用「账号登录密码」进行 Git HTTPS 推送认证。根据系统和 Git 安装方式，可以通过浏览器配合 **Git Credential Manager** 登录，或使用 **Personal Access Token（PAT）**，也可以为 GitHub 配置 **SSH 公钥认证**。**不要把 Token、私钥写进仓库，也不要粘贴到公开聊天或截图中**。


### 9.9 `.gitignore` 是什么？

**通俗理解**：告诉 Git，哪些**还没有被跟踪**的文件通常不需要纳入版本管理，例如临时日志、本地配置。

示例 `.gitignore`：

```gitignore
*.log
.env
.DS_Store
```

**提醒**：`.gitignore` 不能自动删除已经提交过的敏感信息；如果密码或密钥已经泄露，应该立即撤销/轮换，并按正确流程清理历史。

### 9.10 常见 Git 报错

- `fatal: not a git repository`：当前目录不是 Git 仓库。先确认 `pwd`，进入正确项目目录。
- `nothing to commit`：当前没有新的可提交改动，不一定是错误。
- `remote origin already exists`：远程仓库名称 `origin` 已存在；先运行 `git remote -v`，不要重复添加。
- `src refspec main does not match any`：可能还没有成功提交，或当前分支不叫 `main`。
- `Authentication failed`：检查登录方式、凭据权限或 SSH 密钥，不要直接用 GitHub 网页登录密码代替 Token。
- `non-fast-forward`：远端有本地尚未整合的提交，先了解 `git pull` 与冲突解决；不要不理解就执行强制推送。

### 10.3 遇到问题的通用排查路线

```text
问题发生在哪一层？
├─ 文件打不开 → 后缀、真实格式、权限、运行环境、CPU 架构
├─ 命令运行不了 → 当前 Shell、PATH、依赖、命令拼写、权限
├─ 网站打不开 → 网络 → DNS → 端口 → TLS → HTTP → 代理
├─ SSH 连不上 → 地址/路由 → 端口/防火墙 → 服务 → 用户认证
├─ VNC 没画面 → 服务状态 → 桌面会话 → 端口 → 认证/加密
├─ Clash 没生效 → 流量入口 → 路由规则 → 节点/出口 → DNS
└─ Git 推不上去 → 本地提交/分支 → remote → 网络 → 身份验证 → 远端冲突
```
