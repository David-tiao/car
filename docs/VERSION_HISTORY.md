## 3. 主版本号究竟是什么

不要写成“目前整车 V15.0、所有五轴已实机完成”。可采用以下写法：

- **软件集成基线**：`car/main@1a7a696b`（2026-11-21 已合并）
- **网页引擎**：`sim2real/VERSION.txt = 13.0.0`，具体 UI 静态资产各有缓存版本号
- **赛场地图**：正式地图 V5，V6 静态核对版尚不是自动发布
- **OpenMV↔STM32**：V4 默认，V5 旧实验兼容
- **TEST 串口**：CAR-LINK V1/模拟 PTY；**REAL 遥测**：ULog43
- **项目阶段**：软件架构和离线集成测试已建立，实机联调待验证

建议未来引入统一发布标签如 `v0.1.0-software-qa` 或 `v0.2.0-hardware-smoke`，但在真正创建 Git tag 和完成对应门禁之前，不应把建议标签写成已发布版本。

## 4. 如何查询版本而不误用旧分支

~~~bash
cd ~/Desktop/car
git fetch origin --prune
git log --first-parent --oneline -20 origin/main
git rev-parse origin/main
git show --stat 8da64acd
git merge-base --is-ancestor 8da64acd origin/main && echo "机械功能已进入 main"
git branch -r
~~~

旧资料中的 `refactor/architecture-v2`、`feat/stm32-pty-fsm-realview-20261120` 等分支名反映当时的工作背景；确认现在的事实必须再次查看 `main` 和最新提交。更多事故与修复细节见 [错误复盘](ISSUES_AND_LESSONS.md)。
